District Explorer

Choose a district to reveal its 50 discovery points.

Reward mechanics are in demo mode. Finding a point changes its status in this browser session and displays a sample reward. It does not mint an NFT, transfer tokens, or award a real on-chain asset. The final production rules should be enforced by a backend or smart contract.
City structure: District 01 is the Central Administrative District. Each of the other 20 districts has 50 points, and each point is designed to hold 200 NFT slots (1,000 × 200 = 200,000 slots). Individual NFT records are not preloaded into this lightweight demo.

Build & Integration Roadmap

What this prototype does today and what needs to be connected for production.

Working in demo

1. City navigation

21 districts, 20 discovery districts, 50 point cards per discovery district, progress bars and session-only point discovery.

Needs backend

2. Real discovery records

Store user identity, point status, anti-cheat checks, reward eligibility and progress in a database or verified smart-contract flow.

Needs NFT indexer

3. 200,000 NFT slots

Load records on demand using pagination. Do not embed 200,000 NFT objects directly into a static HTML file.

Needs smart contract

4. Rewards

Define eligibility, reward amounts, one-time claims, fraud prevention and contract security before distributing real rewards.

Needs chain config

5. Custom network

Set network ID/RPC, wallet support, NFT contract, metadata rules and an indexer for Twinverse Goshen.

Security

6. Private art

A private blockchain alone does not make media confidential. Add authentication, permissions and private storage.
